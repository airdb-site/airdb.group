## 页面顺序与文字方向

1. 紧凑品牌导航：集团概览 / 业务版图 / 技术与产业 / 合作交流 / 联系我们。首页内锚点配合现有 /about、/contact；原内页仍能通过页脚访问。首页提供中文 / 与英文 /en/，使用真实语言切换链接；保留原英文内页 URL。
2. 首屏两行标题：『科技连接产业，／让价值持续生长。』简介：『Airdb 聚焦商业、农业、金融科技与数据服务，探索技术与真实产业的协同发展。』两个 CTA：『探索业务版图』→ #business；『洽谈合作』→ /contact。『有温度的技术实力。』作为品牌短句。
3. 农业地景为生成的愿景示意，显式标注『产业愿景示意』，不称真实基地。图片不能包含客户标识、业绩或虚构设施说明。
4. 『四个方向，一份共同愿景。』四组业务导航，所有 7 个目标域名可识别并独立链接：
   - 商业与分销：airdb.com 国际商业；airdb.cn 国内商业。
   - 现代农业：airdb.net 实体农业。
   - 金融科技：airdb.hk AI 跨境支付与金融科技方向。
   - 数据与技术平台：airdb.io 数据 SaaS / 开源；airdb.dev 文档 / 教程；airdb.id 人员与设备身份。
   旁注『按业务方向组织的网站入口，非法律组织架构图。』不把目标写成现有产品、已持牌支付或成员子公司。必要状态文字应靠近相关内容。
5. 墨绿技术方法区：『让技术走进真实业务。』三步：理解产业（具体场景与需求）→ 构建能力（数据、软件、协作工具）→ 持续验证（以可验证结果推进合作）。不复述四组业务、不编造技术成果。
6. 合作区：产业合作 / 投资交流 / 企业项目 / 创业伙伴四入口，均指向现有 /contact，清楚是沟通入口，不假设新增表单、招募承诺或投资邀约。保留 info@airdb.com 邮件入口。
7. 首页紧凑公司页脚：公司信息 /about、治理与联系 /contact、工程资源 /engineering、原 /solutions 与 /services 等必要内页入口及版权。公益初心在适当品牌文字中保留为文化，不重新设为核心业务。法律信息询问沿用现有真实联系路径，不恢复占位资料。

## 实现边界

- 只重做 group 首页；内页正文、路由和现有联系功能不改。旧首页抽象图、前置尽调清单和重复板块在首页替换；原组件保留给内页或历史使用，不删除共享内容。
- 首页正文、业务数据、CSS 单独隔离；BaseLayout 增加默认不启用的 homeLocale: zh | en 选项与首页专用导航页脚。默认英文布局保持原样，不全局覆盖 :root 或字体。
- 全文使用可选择的 HTML 文本，不以整张概念图代替页面。标题使用中文无衬线字体；墨绿/米白为主，橙色只用于强调和 CTA。
- 320/390/768/1440px：移动端先文字与 CTA、再图片；业务区由双列变单列；方法和合作入口可换行。首页标题控制两行，正文不截断，按钮触达区至少 44px。以 320×640、390×844、768×1024、1440×900 验证首屏标题、简介和两个 CTA 可见；不以挤压成小字实现。
- 本轮增加完整中英文首页与真实语言切换，不增加外部追踪、表单后台、依赖或网站迁移。不虚构规模、客户、牌照、荣誉。
- 独立生成/取得可用的示意资产，保留来源和愿景标注；任何不能验证的目的站状态如实报告，不用未知链接替代。

## 验收及风险

键盘焦点、跳过导航、移动菜单 Escape/展开状态、锚点可见、无 JS 可用、无横向溢出、正常/减少动效、图片失败时文字 CTA 可用。检查 7 个业务域名的准确 URL 和实际可达性，失败不等同业务不存在。共享布局改动需对全部 7 个现有页面做桌面/手机回归。

现有工具：Astro 7.3.5 / TypeScript；build 和 check 脚本可用，无 test 脚本。使用现有本机 Playwright 做针对性浏览器验收，不新增框架。实现采用原生连续实施，最终独立评审；检查及独立评审通过后，按用户新授权直接安全发布 main 并验证线上。

风险：参考图不是现成独立图片资产，需要提取视觉方向重新制作；原英文内页仍保持原语言，中文首页链接明确标注；外部域名内容未必符合目标定位，需要验证但不跨站修改；移动端不应机械照搬桌面拼贴。

## 双语补充
中文 /、英文 /en/；导航、标题、简介、业务卡、CTA、状态、愿景说明、合作入口、页脚、metadata 完整对应。lang=zh-CN/en，独立 canonical、互相 hreflang 及 x-default。原项目无多语言路由约定。语言切换是可刷新、可返回的静态路径，不依赖 JS 或语言存储。四个断点两种语言均验证。
